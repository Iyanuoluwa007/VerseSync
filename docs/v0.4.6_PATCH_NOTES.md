# v0.4.6 — Spoken English parser regression fix + listen.py device fix

## What broke

In the May 5 live session, large-v3 transcribed correctly but **zero
references were detected**. The parser was rejecting natural spoken
phrasings:

| Whisper heard | Should detect | v0.4.5 result |
|---|---|---|
| `Luke 5 5` | LUK 5:5 | (none) |
| `Psalm 145 verse 5` | PSA 145:5 | (none) |
| `Revelation 2 2` | REV 2:2 | (none) |
| `Psalms 150 from verse 1 to 10` | PSA 150:1-10 | (none) |

Root cause: the regex parser expects canonical `Book N:M` form. When a
preacher speaks naturally, the colon is implied. The Yoruba normaliser
already handled this for Yoruba; the English path had no equivalent.

## What's in this patch

### 1. `backend/app/parser/english_spoken.py` (new)

Mirrors `yoruba.py`: a normaliser that rewrites spoken forms into
canonical regex-friendly form before the regex sees them.

- `verse N` → `N`
- `verses N to M` / `verses N through M` → `N-M`
- `from verse N to M` → `N-M`
- `chapter N` → `N`
- `Book N M` (no colon, two adjacent numbers preceded by a word) → `Book N:M`

19 cases verified in isolation. Idempotent on canonical input
(`John 3:16` passes through unchanged). No false positives on
unrelated text (`hello world`, `Read this in 5 minutes`).

### 2. `backend/app/parser/parser.py` (patched in place)

A small surgical change applied by `scripts/apply_v046_parser_patch.py`:
  - Adds `from app.parser.english_spoken import normalize_english_spoken`
  - Calls `digits = normalize_english_spoken(digits)` immediately after
    `digits = words_to_digits(cleaned)`

That's it. The Yoruba pre-pass and the existing `_try_regex` are untouched.

### 3. `scripts/listen.py` (replaced)

Fixes the `STTPipeline accepts no device kwarg` warning. The pipeline's
constructor doesn't take a device — `pipeline.start(device=…)` does.
The new listen.py:
- Builds the pipeline cleanly (signature-aware, only passes kwargs the
  constructor actually accepts).
- Calls `pipeline.start(device=mic_id)` with the resolved mic.
- No more spurious warning. The mic argument finally takes effect.

### 4. `backend/tests/test_english_spoken.py` (new)

29 parametrized cases:
- 22 normaliser-direct tests
- 7 end-to-end parse() tests including all four live-session failures
- Regression coverage for canonical forms and word-form numbers

## Yoruba status

Yoruba detection still has zero hits in the live session, but the
cause is upstream of the parser: Whisper is mishearing word boundaries
("Johan nukini" instead of "Johanu kini"). The parser's Yoruba
normaliser only fires on recognisable marker words; if Whisper smashes
them together, we lose the signal. Two options for v0.4.7+:

1. **Initial-prompt biasing** — pass a Yoruba scripture vocabulary as
   the Whisper `initial_prompt` to bias the model toward correct
   word boundaries. Minimal code change.
2. **Fuzzy ordinal matching** — extend `yoruba.py` to tolerate one
   smashed-word permutation (e.g., recognise `johanukini` as
   `johanu kini`). More invasive.

Recommend option 1 for v0.4.7. Quick to ship, easy to revert.
